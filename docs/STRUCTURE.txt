СТРУКТУРА ПРОЕКТА
Назначение каталогов и файлов
------------------------------------------------------------------------------

Документ перечисляет файлы репозитория с указанием назначения каждого.
Раздел 9 описывает файлы, добавляемые на последующих этапах.


==============================================================================
1. ПРИНЦИП РАЗДЕЛЕНИЯ
------------------------------------------------------------------------------

Каталоги отражают одно правило: механизм отделён от данных, которыми
он управляет. Механизм редактируется редко, перечень — постоянно.

    Механизм (src/)                Данные (вне src/)
    ---------------------------    ---------------------------------
    Router.php                     config/routes.php
    Migrator.php                   migrations/*.sql

Направление зависимостей: Http -> Domain <- Database. Домен зависит
от интерфейса Connection, а не от PDO напрямую. Обратных зависимостей нет:
Domain не знает о существовании HTTP.

Второе правило — код пишется под существующего потребителя. Абстракция
вводится в момент появления второй реализации, метод — в момент первого
вызова. Раздел 9 перечисляет то, что появится на следующих этапах,
и в текущем срезе отсутствует намеренно.


==============================================================================
2. КОРЕНЬ
------------------------------------------------------------------------------

README.md
    Назначение системы, стек, порядок запуска, структура, архитектурные
    решения, дорожная карта.

composer.json
    Требования к платформе (PHP 8.3, pdo_pgsql, curl), автозагрузка PSR-4
    с корнем App\ на src/, PHPUnit в dev-зависимостях.

composer.lock
    Зафиксированные версии зависимостей.

docker-compose.yml
    Пять сервисов: postgres, php-fpm, nginx, воркер очереди, планировщик.
    Зависимость app и worker от healthcheck базы исключает старт приложения
    до готовности кластера PostgreSQL.

.env.example
    Образец окружения: DSN и учётные данные БД. Копируется в .env перед
    первым запуском. Переменные последующих этапов добавляются по мере
    появления соответствующего кода.

.gitignore
    Исключает vendor, логи, .env и локальные рабочие материалы.

3. bin/ — ТОЧКИ ВХОДА КОМАНДНОЙ СТРОКИ
------------------------------------------------------------------------------

bin/migrate
    Применение миграций. Подключает сборку объектного графа, вызывает
    Migrator, печатает список применённых файлов.


==============================================================================
4. config/ — КОНФИГУРАЦИЯ
------------------------------------------------------------------------------

config/config.php
    Единственная точка чтения окружения. Возвращает массив со значениями
    по умолчанию. Разделы: db, log. Функция getenv в остальном коде
    не вызывается. Параметры поставщиков, заглушек и очереди добавляются
    на соответствующих этапах.

config/routes.php
    Карта маршрутов. Полный перечень адресов, доступных извне, в одном файле.
    Обработчик задаётся парой [класс, метод] и разрешается контейнером.


==============================================================================
5. data/ — ИСХОДНЫЕ ДАННЫЕ
------------------------------------------------------------------------------

data/products.json
    Каталог: артикул, наименование, тип, цена, валюта.
    Двенадцать позиций четырёх типов: topup, key, subscription, giftcard.
    Загружается сидером в таблицу products.

data/keys.json
    Пул кодов для выдачи, 50 значений. Распределяется между заглушками
    поставщиков. Ограничение: один код не может быть выдан двум заказам.


==============================================================================
6. docker/ — ОКРУЖЕНИЕ
------------------------------------------------------------------------------

docker/php/Dockerfile
    Образ на базе php:8.3-fpm-alpine. Расширения pdo_pgsql и pcntl,
    composer. Пул php-fpm переведён в статический режим на 24 процесса —
    параллельность требуется для воспроизведения конкурентных сценариев.

docker/nginx/default.conf
    Document root указывает на public. Все запросы направляются в единую
    точку входа. Таймаут чтения от php-fpm установлен выше собственного
    таймаута обращения к поставщику, чтобы соединение не разрывалось раньше
    срабатывания прикладной логики.


==============================================================================
7. public/ — DOCUMENT ROOT
------------------------------------------------------------------------------

public/index.php
    Точка входа HTTP, четырнадцать строк: подключить сборку, получить
    диспетчер, обработать запрос, отправить ответ.

    Единственный файл, доступный по сети. Остальной код расположен вне
    document root и недостижим по HTTP: при отказе php-fpm веб-сервер
    способен отдать содержимое public как текст, но не файлы за его
    пределами.


==============================================================================
8. src/ — ИСХОДНЫЙ КОД
------------------------------------------------------------------------------

src/bootstrap.php
    Точка сборки объектного графа, общая для HTTP, командной строки
    и фоновых процессов. Единственное место, где интерфейсы связываются
    с реализациями. Возвращает настроенный контейнер.

    Connection и Logger зарегистрированы как singleton: соединение с базой
    должно быть общим для всех потребителей в пределах процесса, иначе
    транзакция одного объекта не видит записей другого.

src/Support/ — инфраструктура
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Container.php
    DI-контейнер. Регистрация фабрики через singleton, разрешение через get.
    Зарегистрированные фабрики вызываются один раз и кэшируются; классы
    без регистрации собираются по типам конструктора и не кэшируются.

    Запрос самого контейнера возвращает текущий экземпляр: иначе автосборка
    создала бы пустой контейнер потребителям, объявившим его в конструкторе.

Logger.php
    Структурированный лог: одна строка — один JSON-объект с меткой времени,
    уровнем, именем события и произвольным контекстом. Запись под LOCK_EX:
    файл открыт несколькими процессами одновременно.

src/Database/ — доступ к данным
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Connection.php
    Контракт доступа к БД: select, selectOne, execute, raw, transaction,
    inTransaction. Домен зависит от интерфейса, а не от PDO.

    Метод execute возвращает число затронутых строк. Ноль после
    INSERT ... ON CONFLICT DO NOTHING означает дубликат — на этом
    построена дедупликация платёжных событий.

PostgresConnection.php
    Реализация на PDO. Соединение открывается при первом запросе.
    Вложенные вызовы transaction участвуют во внешней транзакции,
    COMMIT выполняется один раз на нулевой глубине.

    Подготовка запросов выполняется на стороне сервера
    (ATTR_EMULATE_PREPARES отключён).

    Статический метод isUniqueViolation распознаёт SQLSTATE 23505.
    Нарушение уникальности — штатный результат конкурентной вставки,
    а не сбой: оно означает, что запись уже создана другим процессом.

Migrator.php
    Применение .sql из каталога migrations по порядку имён. Выполненные
    отмечаются в таблице migrations. Каждый файл выполняется в транзакции:
    DDL в PostgreSQL транзакционный, поэтому прерванная миграция
    откатывается целиком и не оставляет схему в промежуточном состоянии.

src/Http/ — слой HTTP
~~~~~~~~~~~~~~~~~~~~~

Request.php
    Запрос: метод, путь, разобранное JSON-тело, параметры строки запроса,
    параметры пути, исходное тело. Конструируется из суперглобальных
    переменных либо напрямую — второе используется в тестах.

    Значение объекта — данные запроса; методов доступа сверх свойств нет,
    они добавляются вместе с потребителями.

Response.php
    Ответ: код состояния и тело. Фабрики json и error. Ошибки имеют единый
    формат с машиночитаемым кодом, пригодным для разбора клиентом.

Router.php
    Маршрутизация по регулярным выражениям с плейсхолдерами вида {id}.
    Не содержит ссылок на контроллеры: обработчик передаётся строкой
    и разрешается контейнером, поэтому компонент тестируется изолированно.
    Регистрация методов добавляется по мере появления маршрутов.

Dispatcher.php
    Диспетчеризация: поиск маршрута, разрешение контроллера через контейнер,
    вызов, преобразование непойманного исключения в ответ 500 с записью
    в лог. Принимает Request и возвращает Response, что позволяет покрывать
    маршрутизацию и коды ответов тестами без запуска веб-сервера.

Controller/HealthController.php
    GET /health. Выполняет SELECT 1 и возвращает 200 либо 503 в зависимости
    от доступности базы. Код состояния значим: оркестраторы и балансировщики
    ориентируются на него, а не на тело ответа.

    Проверка ограничена базой. Доступность поставщиков в неё не входит:
    их отказ — штатный сценарий, обрабатываемый повторами и переключением
    на резервного, и не является основанием для перезапуска контейнера.

src/Domain/ — бизнес-логика
~~~~~~~~~~~~~~~~~~~~~~~~~~~

Каталоги Catalog, Ordering, Payment, Delivery, Ledger. Разделение
по бизнес-способностям, а не по типам классов: сведения о выдаче
сосредоточены в одном каталоге, а не рассредоточены по Models,
Services и Repositories.

Заполняется на последующих этапах.

src/Queue/ и src/Stub/
~~~~~~~~~~~~~~~~~~~~~~

Очередь на таблице с воркером и заглушки поставщиков A и B.
Заполняются на последующих этапах.
