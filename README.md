# Ядро магазина цифровых товаров

Платежи, интеграции с поставщиками, каталог, автоматическая выдача товара.
Ниша — маркетплейсы цифровых товаров для геймеров.

Ключевое требование — **однократная выдача под гонками**: сколько бы вебхуков
об оплате ни пришло и сколько бы раз ни отвалился поставщик по таймауту,
покупатель получает ровно один ключ, и ключ не теряется.

## Стек

| | |
|---|---|
| Язык | PHP 8.3, без фреймворка (PSR-4, свой DI-контейнер и роутер) |
| БД | PostgreSQL 16 |
| Очередь | таблица `jobs` в той же БД (`FOR UPDATE SKIP LOCKED`) |
| HTTP | nginx + php-fpm |
| Тесты | PHPUnit 11 |

## Запуск

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec app composer install
docker compose exec app php bin/migrate
docker compose exec app php bin/seed

curl http://localhost:8080/health
```

Веб-панель управления базой: http://localhost:8081 (сервер `db`,
логин `gamer`, пароль `secret`).

## Тесты

```bash
docker compose exec app vendor/bin/phpunit
```

69 тестов на отдельной базе `gamer_market_test`. Данные разработки
не затрагиваются.

Проверка exactly-once под конкуренцией и устойчивости интеграций:

```bash
docker compose exec app php bin/race --parallel=50 --repeat=20
docker compose exec app php bin/failover --repeat=3
```

## Проверка вручную

```bash
# создать заказ
curl -X POST http://localhost:8080/api/orders \
     -H 'Content-Type: application/json' -d '{"sku":"KEY-GTA5"}'

# отправить вебхук оплаты
docker compose exec app php bin/pay --order=ord_... --amount=1990 \
     --url=http://nginx/api/webhooks/payment

# забрать код
curl http://localhost:8080/api/orders/ord_...
```

`bin/pay` эмулирует платёжную систему. Дополнительные ключи: `--status=failed`,
`--event=<id>` для повторной доставки того же события, `--parallel=N`
для одновременной доставки N копий.

## Структура

```
bin/            точки входа CLI: migrate, seed, worker, pay, race, failover
config/         config.php (единственный читатель окружения), routes.php
data/           каталог товаров и пул ключей
docker/         nginx + php-fpm
docs/           архитектура, нагрузочный профиль
migrations/     .sql, применяются по порядку имён, каждая в транзакции
public/         index.php — единственная точка входа HTTP
src/
  Controllers/  тонкие: разобрать запрос, вызвать сервис, отдать HTTP
  Models/       Order, PaymentEvent, Delivery — состояние и правила
  Services/     бизнес-логика: создание заказа, приём вебхука, выдача
  Database/     Connection (контракт) + PostgresConnection + Migrator
  Http/         Request, Response, Router, Dispatcher
  Queue/        очередь на таблице и воркер
  Support/      контейнер, логгер, перевод денежных единиц
  Exceptions/
tests/
```

## Архитектурные решения

- **Dependency Inversion.** Домен зависит от `Connection`, а не от PDO.
  Связывание реализаций — в одном месте, `src/bootstrap.php`.
- **Тонкие контроллеры.** Разобрать запрос, вызвать действие, отдать HTTP.
  Бизнес-логика в `Domain`.
- **Information Expert.** Переходы статусов проверяет сам `Order`,
  а не контроллер и не сервис.
- **KISS, YAGNI.** Свой контейнер вместо пакета, очередь на таблице вместо
  брокера, без репозиториев поверх запросов. Код пишется под существующего
  потребителя: абстракция вводится при появлении второй реализации,
  метод — при первом вызове.
- **Инварианты на уровне БД.** «Выдано один раз» держится
  на `UNIQUE (deliveries.order_id)`, а не на проверке в PHP: между `SELECT`
  и `INSERT` при параллельных запросах проверка не даёт гарантий.
